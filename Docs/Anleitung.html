HU-MultiTenant

Microsoft 365 und Intune für mehrere Tenants aus einer Oberfläche: PowerShell im Tenant-Kontext mit eigener Snippet-Bibliothek, fertige Reports als Extensions und das Ablaufdatum der Client Secrets im Blick.

⚡ Quick ScriptEigene Skripte gegen einen Tenant ausführen – Token, Tenant und Graph-Funktionen sind schon da.
📚 SnippetsSkript-Bibliothek mit Kurzbeschreibung, Suche, Import und Export.
🧩 ExtensionsReports und Aktionen mit Parametern, Dry-Run und Excel-Ausgabe.
🔑 SecretsDPAPI-verschlüsselt, Ablaufdatum je Tenant, Warnung vor Ablauf.

1Einrichten

VoraussetzungJe Tenant eine App-Registrierung mit Client Secret und den nötigen Graph-Berechtigungen – Schritt für Schritt in INSTALL.md im Programmordner.

Tenant anlegen

  1. ⚙ Einstellungen › Reiter Tenants › + Neu
  2. Anzeigename, Schlüssel (kurz, eindeutig, z. B. Schule-1 – so heißt der Tenant in Skripten als $TenantKey), Tenant-ID, Anwendungs-ID, Domäne.
  3. 🔐 Secret eingeben … – Wert einfügen. Gespeichert DPAPI-verschlüsselt in %APPDATA%\HU-MultiTenant\, nur für deinen Windows-Benutzer auf diesem PC lesbar.
  4. Verbindung + Secret prüfen – zeigt Anmeldung, Anzahl Berechtigungen und das Ablaufdatum.
  5. Speichern

Verknüpfung

⚙ Einstellungen › Allgemein › Desktop-Verknüpfung oder Startmenü-Eintrag. Dabei entsteht HU-MultiTenant.exe im Programmordner: eigenes Logo, kein Konsolenfenster, an die Taskleiste anheftbar. Ohne Administratorrechte.

3Quick Script

Eigene PowerShell-Skripte direkt gegen einen Tenant – in einem eigenen Runspace, die Oberfläche bleibt bedienbar.

  1. Tenant oben im Reiter wählen (eigene Auswahl, unabhängig von den Extensions).
  2. Snippet wählen oder Skript in den Editor schreiben.
  3. Strg+Enter – verbindet bei Bedarf automatisch und führt aus. Ausgabe erscheint Zeile für Zeile, Esc bricht ab. Alle Tasten: Tastenkürzel.

Eigene Snippets schreiben

Im Skript stehen $Token, $TenantKey und die Graph-Funktionen schon bereit. Alles zum Schreiben – Funktionen, Regeln, Parameter, Vorlagen – steht in SNIPPET-DEVELOPMENT.md im Programmordner (online: GitHub).

Mehrere Tenants

Mehrere ▾ öffnet eine Liste mit Haken. Ab zwei Haken läuft das Skript nacheinander je Tenant – $Token und $TenantKey gelten jeweils für den laufenden Tenant. Ausgegebene Objekte bekommen die Spalte Tenant, ein Fehler bricht nur diesen Tenant ab. Keine schaltet zurück auf die Einzelauswahl.

Parameter

Enthält ein Snippet Zeilen wie # @param Tage|int|Ohne Sync seit Tagen|30, erscheinen über dem Editor Eingabefelder. Die Werte bleiben je Snippet gemerkt, solange das Programm läuft.

Echter LaufIst ein Haken DryRun, WhatIf, Probelauf o. ä. aus, fragt das Tool vor dem Start nach. Setzt der Code die Variable selbst ($DryRun = …), wirkt das Feld nicht – das steht dann in der Ausgabe.

Tabelle und Export

Gibt das Skript Objekte aus ([pscustomobject], Select-Object), wird 📊 Tabelle aktiv: Filter über alle Spalten, CSV … (Semikolon, UTF-8), Excel … (benötigt das Modul ImportExcel) und Kopieren für Excel.

Verlauf

🕒 Verlauf zeigt alle Läufe mit Zeit, Snippet, Tenants, Dauer und Ergebnis. Doppelklick öffnet das komplette Protokoll (Logs\QuickScript\, aufbewahrt wie das Tagesprotokoll, Standard 30 Tage).

Write-Host -ForegroundColor erscheint farbig, Write-Warning orange, Fehler rot mit Zeilennummer. Ausgabe kopieren legt die ganze Ausgabe in die Zwischenablage. Rechtsklick in die Ausgabe (auch im Protokoll der Extensions): Kopieren, Alles kopieren, Ausgabe leeren.

4Snippets

Die Auswahl oben im Reiter lädt ein Snippet sofort. Darunter stehen Name und Kurzbeschreibung; ein oranger Punkt ● bedeutet ungespeicherte Änderungen – beim Wechseln und Beenden fragt das Tool nach.

KnopfWirkung
Neuleerer Editor

Verwalten

  • Favoriten: auf den Stern ☆ in der Zeile klicken (oder ★ Favorit für alle markierten). Favoriten stehen in der Auswahl im Quick Script ganz oben; nur Favoriten filtert die Liste. Im Quick Script schaltet der Stern vor dem Namen das geladene Snippet um.
  • Suche in Name, Beschreibung und Code
  • Eintrag markieren → Name / Kurzbeschreibung ändern → Änderung übernehmen; rechts die Code-Vorschau
  • ▲ ▼ Reihenfolge, A-Z, Neueste zuerst, Duplizieren, 🗑 Löschen (mehrere mit Strg/Umschalt)
  • Exportieren … markierte (oder alle) als JSON, Importieren … fügt hinzu – gleiche Namen: ersetzen oder als Kopie
  • Kategorien: Feld Kategorie (oder vorhandene wählen) → übernehmen, gilt für alle markierten. Die Liste ist nach Kategorien gruppiert und filterbar.
  • Beispiele lädt 12 fertige Snippets (Kategorie Beispiele) – vorhandene gleichen Namens bleiben unangetastet.
  • Verlauf zeigt die Läufe des markierten Snippets; darunter steht Zuletzt ausgeführt.
  • Doppelklick oder ▶ Im Editor öffnen lädt das Snippet

5Extensions

  1. Tenant in der Tenant-Leiste wählen.
  2. Extension links wählen – rechts stehen Beschreibung, benötigte Berechtigungen und Parameter.
  3. Optional DRY-RUN (nur Vorschau, bei Extensions, die das unterstützen).
  4. ▶ STARTEN – läuft im Hintergrund, Fortschritt im Protokoll. Reports landen in Reports\HU-Reports_JJJJ-MM-TT\ (Knopf Reports).

Kennzeichen in der Liste: DRY-RUN = Vorschau möglich, BATCH = für mehrere Tenants geeignet, SCHREIBT = verändert den Tenant (vor dem Start zusätzliche Rückfrage).

Berechtigungen

🛠 Berechtigungen zeigt je Tenant, welche Graph-Anwendungsberechtigungen erteilt sind – mit Risiko, Beschreibung und welche Extension sie nutzt. Ist eine Extension gewählt, steht oben, ob ihre Berechtigungen vorhanden sind. Alle Tenants vergleichen zeigt alles in einer Tabelle. Verbinden ist dafür nicht nötig. Nach einer Änderung in Entra (Administratorzustimmung) ↻ Neu lesen.

Eigene Extensions

Vorlage Extensions\Template.ps1 kopieren, Kopf ausfüllen (.REQUIRED_PERMISSIONS, .PARAM, .DRY_RUN_CAPABLE, .MODE, .RUNTIME) und ↻ drücken. Details: EXTENSION-DEVELOPMENT.md. Eigene Extensions bleiben bei Updates erhalten.

6Apps verteilen

Programme (MSI, EXE) und Microsoft-Store-Apps an eine oder mehrere Schulen verteilen – das Paket wird einmal gebaut und in jede gewählte Schule hochgeladen.

  1. + Setup-Datei (oder die Datei auf die Liste ziehen). Name, Version, Hersteller, Installations- und Deinstallationsbefehl und die Erkennung werden ausgelesen – bei MSI vollständig, bei EXE der Installer-Typ mit stillem Schalter (Inno, NSIS, InstallShield, WiX, Advanced Installer, Squirrel).
  2. 🧪 Testinstallation in der Windows Sandbox – das Setup läuft in einem Wegwerf-Windows, dein PC bleibt sauber. Danach schlägt das Tool Erkennung und Deinstallation vor (Übernehmen?). Mit Deinstallation mittesten wird auch der Deinstallationsbefehl geprüft.
  3. Schulen anhaken, Ziel wählen (Gruppe – wird in jeder Schule per Name gesucht –, Alle Geräte oder Alle Benutzer) und Erforderlich, Verfügbar (Unternehmensportal) oder Deinstallieren.
  4. ⬆ Hochladen & zuweisen. Fortschritt erscheint unten; die Geräte holen die App beim nächsten Sync.
  5. 📊 Status zeigt je Gerät, ob die Installation geklappt hat – mit Fehlertext und Export (der Intune-Bericht braucht nach dem Zuweisen oft 1–2 Stunden).

Symbol im Unternehmensportal

Rechts neben Name und Hersteller: Symbol … nimmt ein Bild (PNG, JPG), eine ICO-Datei oder eine EXE – es wird als PNG mit höchstens 256 px gespeichert und beim Hochladen gesetzt. Automatisch: bei EXE-Setups aus der Setup-Datei, nach der Testinstallation aus der installierten App (wird beim Übernehmen mit vorgeschlagen), bei Store-Apps aus dem Microsoft Store. Ein geändertes Symbol wird beim nächsten ⬆ Hochladen & zuweisen übernommen.

Neue Version

Die neue Setup-Datei hinzufügen und bei gibt es schon Ja wählen: dieselbe Intune-App wird aktualisiert (neue Version, neue Erkennung, neues Paket). Unveränderte Pakete werden nicht erneut hochgeladen.

Pilotgruppe (optional)

Haken zuerst nur an Pilotgruppe: die App geht erst an diese Gruppe. Passt alles, ergänzt Für alle freigeben das eigentliche Ziel.

Store-Apps

+ Store-App, auf apps.microsoft.com die App suchen und die Adresse (oder nur die ID, z. B. 9NKSQGP7F2NH) bei Store-ID einfügen – Name und Hersteller werden ergänzt. Store-Apps brauchen kein Paket und aktualisieren sich selbst.

Windows Sandbox

Die Testinstallation läuft immer in der Sandbox. Ist sie nicht aktiviert, öffnet sich ein Fenster mit Sandbox jetzt aktivieren (Administratorrechte, danach Neustart). Voraussetzung: Windows 10/11 Pro, Education oder Enterprise mit eingeschalteter Virtualisierung. Es läuft immer nur eine Sandbox gleichzeitig.

Einmalig: Paketier-WerkzeugBeim ersten Hochladen fragt das Tool, ob es das Microsoft Win32 Content Prep Tool von GitHub laden darf (Microsoft erlaubt keine Weitergabe). Die Signatur wird geprüft, Ablage in Tools\.
BerechtigungenDeviceManagementApps.ReadWrite.All und Group.Read.All (Gruppen per Name finden).

7Wartung (Remediations)

Wartungspakete prüfen regelmäßig etwas auf den Geräten und reparieren es bei Bedarf – z. B. volle Festplatte, abgeschalteter Dienst. Ein Paket besteht aus Prüfskript (exit 1 = Problem) und optional Reparaturskript; ohne Reparatur wird nur berichtet.

  1. + Neu oder Beispiele … (fünf fertige Pakete).
  2. Mit KI erstellen: Aufgabe in einem Satz beschreiben → Prompt kopieren → in ChatGPT, Claude oder Copilot einfügen → Antwort kopieren → Antwort einfügen. Die Antwort wird automatisch in Prüf- und Reparaturskript aufgeteilt; der Prompt enthält alle Intune-Regeln.
  3. ✔ Prüfen findet typische Fehler (fehlendes exit 1, Neustart, Eingaben, PowerShell-7-Syntax, Benutzerpfade unter SYSTEM). Prüfskript hier ausführen testet nur das Prüfskript auf deinem PC.
  4. Schulen, Ziel, Zeitplan (täglich, stündlich, einmal) und Kontext wählen → ⬆ Hochladen & zuweisen (optional zuerst Pilotgruppe, später Für alle freigeben).
  5. 📊 Ergebnisse: je Gerät kein Problem, Problem gefunden, behoben, Fehler und die Ausgabe des Skripts – mit Export.
  6. ▶ Jetzt auf Gerät … startet das Paket sofort auf einem oder mehreren Geräten (müssen online sein; Geräte aus den Ergebnissen mit Problem stehen oben).
Lizenz und BerechtigungenRemediations brauchen Windows Enterprise/Education E3/A3 (oder höher) und einmal je Schule im Intune Admin Center: Mandantenverwaltung › Connectors und Token › Windows-Datenverarbeitung › Windows-Lizenzüberprüfung einschalten. Berechtigungen: DeviceManagementScripts.ReadWrite.All, Group.Read.All; für Jetzt auf Gerät zusätzlich DeviceManagementManagedDevices.PrivilegedOperations.All.

8Secrets und Ablaufdatum

Neben dem Tenant steht, bis wann das Client Secret gültig ist. Gewarnt wird ab 30 Tagen (einstellbar): orange neben dem Tenant und in der Titelleiste, ab 7 Tagen rot.

QuelleWie
Graphbeim Verbinden und beim Start (im Hintergrund, höchstens einmal am Tag). Das verwendete Secret wird an seinen ersten 3 Zeichen erkannt – hat die App mehrere Secrets, zählt genau das gespeicherte. Braucht Application.Read.All.
manuellEinstellungen › Tenants › Secret gültig bis – wenn die Berechtigung fehlt

Secret erneuern

  1. Entra: neuen geheimen Clientschlüssel anlegen (Knopf Entra Admin Center im Secret-Dialog öffnet die richtige Seite).
  2. Einstellungen › Tenants › 🔐 Secret eingeben … – neuen Wert einfügen.
  3. Verbindung + Secret prüfen – neues Datum wird angezeigt. Altes Secret in Entra löschen.
AbgelaufenMit abgelaufenem Secret gibt es keinen Token – Verbinden meldet „Kein Token – Secret prüfen“.

9Update

Beim Start wird im Hintergrund nach Updates gesucht; bei einer neuen Version wird Update gold. Klick: HU-MultiTenant schließt sich, Pull.ps1 lädt alle Dateien, prüft jede gegen die SHA-256-Liste und die Signatur des Herausgebers und ersetzt erst dann. Danach startet das Tool neu.
